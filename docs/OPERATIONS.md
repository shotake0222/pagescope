# PageScope 運用フロー

ユーザーの「申し込み → ログイン → 利用」と、運営側の対応手順をまとめたものです。
URL の先頭は本番環境のドメインに読み替えてください。

- 現在: `https://pagescope.straid-nfc-companion.workers.dev`
- 独自ドメイン切り替え後: `https://pagescope.online`

---

## 1. 基本方針

- **無料プランはありません。** アカウントはすべて、契約（入金確認）後に運営が `/admin` で発行します。LP からのセルフ登録はありません。
- **プランの違いは監視できるドメイン数だけです。** AI サマリー・スクリーンショット・即時パトロール・自動パトロール（1時間に1回）は全プラン共通です。
- **Slack 通知はありません。** 変更はダッシュボードのタイムラインと共有 URL で確認します。
- 商談相手などに試してもらう場合は、運営がスタートプランのアカウントを発行し、運営用メモに「デモ／期限 ○/○」と書いて管理します。期限が来たら `/admin` で削除します。

## 2. 画面一覧

| 対象 | 画面 | パス | ログイン |
| --- | --- | --- | --- |
| 誰でも | LP（サービス紹介・料金・お申し込みフォーム） | `/` | 不要 |
| 誰でも | ログイン | `/login` | 不要 |
| 誰でも | パスワードを忘れた場合 | `/forgot` | 不要 |
| 誰でも | 共有レポート | `/share/<トークン>` | 不要 |
| 誰でも | サンプルレポート | `/share/demo-token` | 不要 |

| ユーザー | アカウント設定（契約内容・パスワード変更） | `/settings` | 必要 |

| 運営 | 稼働確認（DB・設定の状態） | `/healthz` | 不要 |

`/signup` は廃止しており、開くとお申し込みフォーム（`/#contact`）へ移動します。

## 4. 申し込みから利用開始まで

```
【ユーザー】LP の「お申し込み」→ フォームで「ご用件」にプランを選んで送信
     ↓（Formspree 経由で運営にメールが届く）
【運営】請求書（PDF）をメールで送付
     ↓
【ユーザー】銀行振込
     ↓
【運営】入金を確認 → /admin でアカウント発行 → ログイン情報をメールで連絡
     ↓
【ユーザー】/login でログイン → 監視したいLPを登録 → 利用開始
```

### 4-1. ユーザー：申し込み
1. LP 右上の「お申し込み」、ヒーローの「差分調査の自動化を申し込む」、または料金表の「このプランを申し込む」を押す（いずれもページ下部のフォームへ移動）
2. お名前／会社名・メールアドレス・ご用件（プラン）・お問い合わせ内容を入力して「送信する」

### 4-2. 運営：アカウント発行
1. 入金を確認したら `/admin` にログイン
2. 「新規アカウント発行」にメールアドレスとプランを入力して「アカウントを作成する」
3. 画面に **初期パスワード（14文字）** が表示される。この画面を閉じると再表示できないので、必ずコピーする
4. 一覧の運営用メモに「2026/10/20 入金 / 2026/10〜2027/01（3ヶ月）」のように契約内容を記録して「保存」
5. ユーザーへ次の内容をメールで連絡する

```
件名：【PageScope】ご利用開始のご案内

ログインURL：https://pagescope.online/login
メールアドレス：（登録したアドレス）
初期パスワード：（表示されたパスワード）

ログイン後、右上の歯車アイコン「アカウント設定」から
パスワードの変更をお願いいたします。
```

### 4-3. ユーザー：ログイン
1. `/login` でメールアドレスと初期パスワードを入力
2. `/settings` でパスワードを変更（8文字以上）
3. ログイン状態は 30 日間保持されます。パスワードを 10 回間違えると 15 分間ログインできなくなります

### 4-4. ユーザー：利用
1. **監視の登録**：ダッシュボード左の「新規パトロールLP登録」に、名称・URL・（任意で）CSS セレクタを入力
   - セレクタ例：`.price-box`、`#main-catchcopy`、`main .plan`、`.a, .b`（空欄ならページ全体）
2. **初回データの保存**：右上の「即時パトロール実行」を押す（押さなくても1時間以内の自動パトロールで保存されます）
3. **変更の確認**：変更が検知されると、タイムラインに AI サマリー付きのレポートが追加されます
   - 「詳細ビュー」で変更前後の差分とスクリーンショットを確認
   - 「コピー」で共有 URL（ログイン不要）をコピーし、チームやクライアントに送れます
4. **取得エラー**：URL が開けない、セレクタに一致しない等の場合は、監視リストの該当カードに赤字で理由が表示されます
5. **上限**：プランのドメイン数に達すると、新規登録ボタンが押せなくなります。不要な監視を削除するか、プラン変更を申し込んでもらいます

## 5. プラン変更

1. ユーザーがフォームで「ご用件：プラン変更」を送信
2. 運営が差額の請求書を送付 → 入金確認
3. `/admin` の一覧で該当ユーザーのプランを選び、メモを更新して「保存」
4. ユーザーが次にダッシュボードを開いた時点で上限が変わっている

ダウングレードで監視件数が上限を超える場合、既存の監視は止まりませんが、新規登録はできなくなります。必要に応じてユーザーに削除を依頼してください。

## 6. パスワードを忘れた場合

### メール送信を設定していない場合（現在）
1. ユーザーが `/forgot` を開く →「お問い合わせフォームからご連絡ください」と表示される
2. ユーザーがフォームで「ご用件：パスワード再発行」を送信
3. 運営が本人確認（登録メールアドレスから送られているか等）をしてから、`/admin` の「パスリセット」を押す
4. 表示された新しいパスワードをユーザーに連絡（それまでのログインはすべて解除されます）

### メール送信を設定した場合（Resend）
`RESEND_API_KEY` を登録すると、`/forgot` でメールアドレスを入力するだけで再設定リンク（1時間有効）が届くようになり、運営の対応は不要になります。

## 7. 解約・契約終了

`/admin` →「削除」。そのユーザーの監視対象・検知履歴・スクリーンショット・ログイン状態がすべて削除されます。元に戻せません。
共有済みのレポート URL も開けなくなるので、必要ならユーザーに事前に保存してもらってください。

## 8. 日常の確認とトラブル対応

| 確認すること | 方法 |
| --- | --- |
| サービスが正常か | `/healthz` を開き `"ok": true`、`admin_configured` / `gemini_configured` が `true` か |
| 自動パトロールが動いているか | `/admin` 上部の「取得エラー」件数、ユーザーのダッシュボードの「最終チェック」時刻 |
| エラーの詳細 | Codespaces で `npx wrangler tail --format pretty` を実行してエラーを再現する。または Cloudflare ダッシュボード → Workers → pagescope →「ログ」 |
| 契約期限 | `/admin` の運営用メモ |

### よくあるエラー
- **「エラーが発生しました（エラーID: xxxxxxxx）」**：ログでそのエラーIDを検索すると原因が出ます
- **`/healthz` が `"database": "テーブル未作成"`**：通常は最初のアクセスで自動作成されます。直らない場合は `npm run db:migrate:remote`
- **Cloudflare のエラー 1102（CPU 制限超過）**：Workers 無料プランの CPU 時間（1リクエスト 10ms）を超えています。Workers Paid（月 $5）への切り替えを推奨します
- **AI サマリーが「APIエラー」**：Gemini の混雑や上限によるものです。差分そのものは保存されています。続く場合は Gemini API キーと利用上限を確認してください

## 9. 運用上の設定（`wrangler.jsonc` の `vars`）

変更後は `npm run deploy` で反映します。

| 設定 | 現在値 | 内容 |
| --- | --- | --- |
| `PASSWORD_HASH_ITERATIONS` | `"20000"` | Workers Paid に切り替えたら `"100000"` に上げる（既存ユーザーは次回ログイン時に自動で切り替わる） |
| `PATROL_BATCH_SIZE` | `"15"` | 1回の自動パトロール（10分ごとに起動）で処理する最大件数。監視の総数が増えたら引き上げる（目安：総数 ÷ 6） |
| `FORMSPREE_ID` | `"xgaedrrr"` | お申し込みフォームの送信先 |

秘密情報（`GEMINI_API_KEY`、`ADMIN_USER`、`ADMIN_PASSWORD` など）は `npx wrangler secret put <名前>` で変更します。

## 10. 検証記録

2026-10-18、テーブル未作成の空のデータベースから、ローカル環境で次の 40 項目をすべて確認しました（Gemini・PageSpeed は応答を模したテスト用サーバーを使用）。

- **初期状態**：最初のアクセスでテーブルが自動作成され、`/healthz` が正常になる
- **申し込み**：LP に「無料」の案内がない、`/signup` はフォームへ移動し登録はできない、申し込みボタンはすべてフォームへ、フォームにプラン選択がある、料金表は3プランで機能は共通（1時間に1回）、Slack の表記がない
- **アカウント発行**：管理者ログイン、プラン選択肢、14文字の初期パスワード表示
- **ログイン**：ログイン画面に新規登録リンクがない、初期パスワードでログインできる、スタートプランは1件、自動パトロール1時間に1回と表示
- **利用**：監視登録、上限超過は拒否、初回保存 → 価格変更の検知 → AI サマリーとスクリーンショットが保存され、共有レポートをログインなしで開ける
- **設定**：Slack の設定がない、月額が表示される、パスワード変更
- **プラン変更**：ライトに変更すると上限5件になり2件目を登録できる、旧データの `free` はスタート扱い
- **パスワード再発行**：`/forgot` は運営への連絡を案内、パスリセットで旧ログインが解除され新パスワードでログインできる
- **自動パトロール**：前回チェックから30分の対象は処理せず、61分の対象だけ処理する
- **解約**：削除するとログインできず、共有レポートも開けなくなる

本番では、デプロイのたびに次を確認してください：
`/healthz` が ok → `/admin` でテスト用アカウントを発行 → そのアカウントでログイン → 監視登録 → 即時パトロール → `/admin` でテスト用アカウントを削除
