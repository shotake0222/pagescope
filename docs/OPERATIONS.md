# PageScope 運用フロー

ユーザーの「申し込み → ログイン → 利用」と、運営側の対応手順をまとめたものです。
URL の先頭は本番環境のドメインに読み替えてください。

- 現在: `https://pagescope.straid-nfc-companion.workers.dev`
- 独自ドメイン切り替え後: `https://pagescope.online`

---

## 1. 画面一覧

| 対象 | 画面 | パス | ログイン |
| --- | --- | --- | --- |
| 誰でも | LP（サービス紹介・料金・お問い合わせ） | `/` | 不要 |
| 誰でも | 無料アカウント作成 | `/signup` | 不要 |
| 誰でも | ログイン | `/login` | 不要 |
| 誰でも | パスワードを忘れた場合 | `/forgot` | 不要 |
| 誰でも | 共有レポート | `/share/<トークン>` | 不要 |
| 誰でも | 共有レポートのデモ | `/share/demo-token` | 不要 |
| ユーザー | ダッシュボード（監視登録・タイムライン） | `/dashboard` | 必要 |
| ユーザー | アカウント設定（パスワード変更・Slack 通知） | `/settings` | 必要 |
| 運営 | 管理画面（ユーザー発行・プラン変更・パスリセット・削除） | `/admin` | 管理者ID |
| 運営 | 稼働確認（DB・設定の状態） | `/healthz` | 不要 |

## 2. プラン

システム上のプランは 3 種類です（設定は `src/lib/plans.ts`）。

| プラン | 監視上限 | 自動パトロール | AI サマリー / スクショ / Slack |
| --- | --- | --- | --- |
| Free | 1 件 | 1日に1回 | あり |
| Light | 5 件 | 1時間に1回 | あり |
| Business | 30 件 | 10分ごと | あり |

どのプランでも、ダッシュボードの「即時パトロール」でいつでも手動チェックできます（同じ対象は60秒に1回まで）。

---

## 3. ユーザーの流れ（無料で始める）

`ALLOW_SIGNUP` が `"true"`（現在の設定）のときの流れです。

```
LP「無料登録」 → /signup でアカウント作成 → そのまま /dashboard へ（ログイン済み）
   → 監視したいLPを登録 → 即時パトロールで初回データ保存
   → 以降は自動パトロール → 変更があればタイムラインにレポート＋Slack通知
```

### 3-1. 申し込み（アカウント作成）
1. LP 右上の「無料登録」またはヒーローの「今すぐ無料で差分調査を自動化する」を押す → `/signup`
2. メールアドレスとパスワード（8文字以上）を入力して「フリープランでアカウント作成」
3. 自動的にログインし、ダッシュボードが開く（Free プラン・監視枠 1 件）

- 同じメールアドレスでは二重登録できません
- 同じ IP からの大量登録は 15 分あたり 10 回までに制限されます
- メールアドレスの確認（本人確認メール）は行っていません。必要になったら追加を検討します

### 3-2. ログイン
1. `/login` でメールアドレスとパスワードを入力
2. ログイン状態は 30 日間保持されます
3. パスワードを 10 回間違えると、15 分間ログインできなくなります（総当たり対策）

### 3-3. 利用
1. **監視の登録**：ダッシュボード左の「新規パトロールLP登録」に、名称・URL・（任意で）CSS セレクタを入力
   - セレクタ例：`.price-box`、`#main-catchcopy`、`main .plan`、`.a, .b`（空欄ならページ全体）
2. **初回データの保存**：右上の「即時パトロール実行」を押す（押さなくても次の自動パトロールで保存されます）
3. **変更の確認**：変更が検知されると、タイムラインに AI サマリー付きのレポートが追加されます
   - 「詳細ビュー」で変更前後の差分とスクリーンショットを確認
   - 「コピー」で共有 URL（ログイン不要）をコピーし、チームやクライアントに送れます
4. **Slack 通知**（任意）：`/settings` に Slack の Incoming Webhook URL を登録 →「テスト送信」で確認
5. **取得エラー**：URL が開けない、セレクタに一致しない等の場合は、監視リストの該当カードに赤字で理由が表示されます

### 3-4. パスワードの変更
`/settings` →「パスワード変更」。変更すると、ほかの端末のログインは自動的に解除されます。

## 4. 有料プランへの切り替え（請求書払い）

```
ユーザー：LP のお問い合わせフォームで希望プランを送信
  → 運営：Formspree 経由でメールを受信
  → 運営：請求書（PDF）をメールで送付
  → ユーザー：銀行振込
  → 運営：入金確認後、/admin でプラン変更（＋メモに入金日・契約期間）
  → ユーザー：次にダッシュボードを開いた時点で上限が増えている
```

運営の操作：
1. `/admin` にログイン
2. 「登録ユーザー一覧」で該当ユーザーのプランを選び、運営用メモに「2026/10/20 入金 / 2026/10〜2027/01（3ヶ月）」のように記録して「保存」
3. ユーザーへ「アップグレードが完了しました」と連絡

契約終了時は、同じ画面でプランを Free に戻します。監視件数が上限を超えている場合、既存の監視は止まりませんが、ユーザーは新規登録ができなくなります（削除して枠を空ける必要があります）。

## 5. 運営がアカウントを発行する場合

法人契約で先に請求書を発行する場合や、`ALLOW_SIGNUP` を `"false"` にしてセルフ登録を閉じた場合の流れです。

1. `/admin` →「新規アカウント発行」にメールアドレスとプランを入力して「アカウントを作成する」
2. 画面に **初期パスワード（14文字）** が表示される。この画面を閉じると再表示できないので、必ずコピーする
3. ユーザーへ、ログイン URL（`/login`）・メールアドレス・初期パスワードを連絡
4. ユーザーにはログイン後、`/settings` でパスワードを変更してもらう

---

## 6. パスワードを忘れた場合

### メール送信を設定していない場合（現在）
1. ユーザーが `/forgot` を開く →「お問い合わせフォームからご連絡ください」と表示される
2. ユーザーがお問い合わせフォームで登録メールアドレスを連絡
3. 運営が本人確認（登録メールアドレスから連絡が来ているか等）をしてから、`/admin` の「パスリセット」を押す
4. 表示された新しいパスワードをユーザーに連絡（それまでのログインはすべて解除されます）

### メール送信を設定した場合（Resend）
`RESEND_API_KEY` を登録すると、`/forgot` でメールアドレスを入力するだけで再設定リンク（1時間有効）が届くようになり、運営の対応は不要になります。

---

## 7. 解約・アカウント削除

`/admin` →「削除」。そのユーザーの監視対象・検知履歴・スクリーンショット・ログイン状態がすべて削除されます。元に戻せません。
削除すると、以前に共有したレポート URL も開けなくなります。

## 8. 日常の確認とトラブル対応

| 確認すること | 方法 |
| --- | --- |
| サービスが正常か | `/healthz` を開き `"ok": true` になっているか。`admin_configured` / `gemini_configured` が `true` か |
| 自動パトロールが動いているか | `/admin` 上部の「取得エラー」件数、またはユーザーのダッシュボードの「最終チェック」時刻 |
| エラーの詳細 | Codespaces で `npx wrangler tail --format pretty` を実行し、エラーを再現する。または Cloudflare ダッシュボード → Workers → pagescope →「ログ」 |

### よくあるエラー
- **「エラーが発生しました（エラーID: xxxxxxxx）」**：ログでそのエラーIDを検索すると原因が出ます
- **`/healthz` が `"database": "テーブル未作成"`**：通常は最初のアクセスで自動作成されます。直らない場合は `npm run db:migrate:remote`
- **Cloudflare のエラー 1102（CPU 制限超過）**：Workers 無料プランの CPU 時間（1リクエスト 10ms）を超えています。Workers Paid（月 $5）への切り替えを推奨します
- **AI サマリーが「APIエラー」**：Gemini の混雑や上限によるものです。差分そのものは保存されています。続く場合は Gemini API キーと利用上限を確認してください

## 9. 運用上の設定（`wrangler.jsonc` の `vars`）

変更後は `npm run deploy` で反映します。

| 設定 | 現在値 | 内容 |
| --- | --- | --- |
| `ALLOW_SIGNUP` | `"true"` | `"false"` にするとセルフ登録を閉じ、LP のボタンはお問い合わせへ移動 |
| `PASSWORD_HASH_ITERATIONS` | `"20000"` | Workers Paid に切り替えたら `"100000"` に上げる（既存ユーザーは次回ログイン時に自動で切り替わる） |
| `PATROL_BATCH_SIZE` | `"15"` | 1回の自動パトロール（10分ごと）で処理する最大件数 |

秘密情報（`GEMINI_API_KEY`、`ADMIN_USER`、`ADMIN_PASSWORD` など）は `npx wrangler secret put <名前>` で変更します。

## 11. 検証記録

2026-10-18、テーブル未作成の空のデータベースから、ローカル環境で次の 46 項目をすべて確認しました（Gemini・PageSpeed は応答を模したテスト用サーバーを使用）。

- **初期状態**：最初のアクセスでテーブルが自動作成され、`/healthz` が正常になる
- **申し込み**：`/signup` で登録 → ダッシュボードへ自動ログイン。短いパスワードと二重登録は拒否
- **利用**：監視登録、Free プランの上限（2件目は拒否）、初回保存 → 価格変更の検知 → 共有レポートに新価格が表示、他人の監視対象は操作不可
- **設定**：Slack URL の検証と保存、パスワード変更（旧パスワードは無効になり、この端末はログイン維持）
- **ログイン / ログアウト**：ログアウト後はダッシュボードに入れない、メールアドレスの大文字小文字を区別しない
- **運営**：管理者ログイン（誤りは拒否）、プランを Light に変更 → ユーザー側の上限が 5 件に、アカウント発行 → 初期パスワードでログイン、パスリセットで旧ログインが解除、削除したユーザーはログイン不可
- **セキュリティ**：外部サイトからの送信を拒否、パスワード 10 回失敗で一時ロック
- **自動パトロール**：Cron 実行で期限の来た対象だけ処理

本番では、デプロイのたびに次を確認してください：
`/healthz` が ok → `/signup` でテスト用アカウント作成 → 監視登録 → 即時パトロール → `/admin` でテスト用アカウントを削除
